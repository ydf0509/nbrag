## 基础篇

### 1. 什么是 RAG？它解决了大模型的哪些痛点？
标准答：Retrieval-Augmented Generation，检索增强生成。先检索外部知识，再把证据拼入 Prompt 生成。
解决四痛：知识截止不新、私域知识没有、幻觉乱编、答案不可追溯。
加分：RAG 是推理时引入外部知识的工程链路，不是向量库加大模型；只能降低幻觉，不能消除。

### 2. RAG 的完整工作流程是什么？
离线索引：文档接入 -> 解析清洗 -> 切块 Chunk -> Embedding 向量化 -> 向量库索引 + metadata/ACL 绑定。
在线：用户 Query -> 查询理解/改写 -> 召回 Top-K -> Rerank 精排 -> 上下文组装 -> LLM 生成 -> 返回引用/trace。
加分：说清索引与检索两条链路，以及 metadata 是名片、ACL 是保安。

### 3. RAG 和微调（Fine-tuning）有什么区别？什么时候用哪个？
RAG：成本低、无需训练、实时更新、可追溯，适合私域、实时、长尾知识。
微调：成本高、更新慢、黑盒，适合风格迁移、领域能力、格式对齐。
可组合：微调学说话方式，RAG 给准确信息。法律分析、客服多用 RAG+微调。

### 4. 基础 RAG 有什么核心局限？
检索不准引入噪声、多跳推理差、上下文溢出、文档冲突、时效更新难、固定单次检索无法自纠。
这是所有进阶方案（Advanced/Self/CRAG/Graph/Agentic）的出发点。

## 切块与解析篇

### 5. Chunk 策略怎么选？size 和 overlap 如何定？
策略：固定大小、按句/段、递归、语义切块、结构化按标题切。
建议：256-1024 Token，overlap 10%-20% 或 50-100 Token防边界丢失。
trade-off：太细信息碎、太粗语义被平均；重叠大冗余多、小则易断在边界。中文要用中文标点优先级分隔。

### 6. PDF 解析为什么是 RAG 第一个大坑？
PDF 面向展示：多栏顺序乱、表格丢结构、扫描件无文字、公式图表难提。
方案：文本用 Tika+后处理、表格用 Camelot、扫描走 PaddleOCR、混合多路合并。表格转 Markdown/JSON 单独索引，标题层级保留为元数据。

## 向量与检索篇

### 7. Embedding 是怎么把文字变向量的？选型看什么？
对比学习把语义相近映射到高维近点，常用余弦相似度。
看：维度、中文支持（BGE/M3E）、上下文长度、速度。专用小模型常胜通用大模型 embedding。
必考：BGE 为何归一化？归一化后余弦=内积，检索更快更稳，否则长度污染排序。

### 8. HNSW 为什么快？与暴力搜索、IVF 如何选？
HNSW 多层图由粗到细，O(log n)。M 管连接数、efSearch 管精度延迟权衡。
选型：<10万暴力即可；10万-千万 HNSW 精度高内存大；亿级 IVF 更省内存。
FAISS 单机极速但难增量，生产多用 Milvus/Qdrant。

### 9. 向量数据库怎么选？Milvus/Chroma/FAISS/Pinecone？
Milvus：全平台、亿级分布式、元数据过滤强、Lite可升级，主推生产。
Chroma：3行跑通，适合原型，百万内、mac Intel 易失败。
FAISS：纯内存离线批处理最快，不支持增量/过滤。
Pinecone：全托管零运维，贵、数据出境慎用。
另：Qdrant 均衡、pgvector 适合 SQL 混合、Weaviate 召回高。

### 10. 混合检索是什么？为什么比纯向量好？
BM25 稀疏精确匹配编号专名 + 向量稠密语义理解，互补。
融合用 RRF：score=Σ1/(k+rank)，只看排名不看绝对分，解决不可比。
纯向量对关键词不敏感，生产标准已是混合检索。

### 11. Rerank 原理？Cross-Encoder 与 Bi-Encoder 区别？
初检双塔独立编码，快但粗；Rerank 交叉编码 Query+Doc 拼一起算，精但贵 10-100 倍。
故两阶段：粗排 Top50-100 -> 精排取 Top5，Hit@5 常从 0.72 提到 0.85。Rerank 不能替代初检，否则百万条算几分钟。

### 12. Query 改写有哪些手段？HyDE 与 Step-back 适用何时？
手段：同义扩展、LLM 多查询变体合并、会话改写为独立查询、HyDE、Step-back。
HyDE：短 Query 先让 LLM 生成假想答案再拿去检索，解决问答向量分布不对称，适合极短模糊 Query。
Step-back：问题太具体先抽象到原理层再回具体，适合词面不稳定多跳。
注意保留原 Query 双路，避免改写漂移。

## 高级范式篇

### 13. Self-RAG 与 CRAG 是什么？与传统 RAG 区别？
传统：每次都检索，易引噪。
Self-RAG：引入反思 Token 自主决策要不要检索、用不用结果，内部反思，需特殊训练，适合问题类型杂。
CRAG：检索质量差时外部纠正，降级 Web 搜索+知识精炼，即插即用，适合覆盖不全容忍延迟。

### 14. GraphRAG 与传统 RAG 有什么区别？
传统只能单跳，难跨文档关联。
GraphRAG：LLM 抽实体关系建图谱，做社区发现层次摘要，检索文本+关系路径，支持 A->B->C 多跳。
适合企业复杂问答。LightRAG 降索引成本，号称降 99.9%。

### 15. Agentic RAG 与普通 RAG 差在哪？
不是加壳，而是文档处理到检索全闭环：语义分块、层级索引、多轮迭代检索、工具调用 API/SQL/图谱/搜索、反思规划。
普通：固定切块、单次检索、无反思、结构丢失。
Agentic：按需分解子问题、多轮查、外部动态注入、RPC 等结果。90% 生产失败多因流程仍是死的。

## 评估与生产篇

### 16. 如何评估 RAG 系统质量？
检索：Recall@k 有无漏、MRR 首个排位、nDCG 排序完美度、HitRate@k 至少命中一个。
生成：Ragas 的 faithfulness 忠实度、answer relevancy 切题、correctness 正确完整、citation accuracy 引用准、hallucination rate、拒答准确率。
系统：P95 延迟、单问成本、索引更新时间、权限错误率。

### 17. RAG 常见失败与解法？
检索空洞：改写/HyDE/多路；召回不准：调块调模型；溢出：压缩摘要+Rerank；冲突：权威加权多视角；过期：增量索引+时间提示；幻觉拼凑：强制引用+Self-RAG。

### 18. 上下文组装与延迟如何权衡？
策略：Rerank 后取 Top3-5、长块截断 Small-to-Big 先定位小块再扩、冲突去重、时间排序。
延迟预算：Embedding+召回毫秒级，Rerank+LLM 是大头，HyDE 多一次 LLM 调用可并行。TopK 大准但贵，需压测定。

### 19. 生产级 RAG 还要考虑什么？
权限：ACL 召回前过滤，不能召回后才藏；增量：加删文档同步向量与索引，保证 embedding 版本一致；监控：funweb 类看积压成功率失败告警；治理：定时 ApsJob 推种子、死信毒丸隔离、过期丢弃、熔断、远程部署、多进程多机叠加。

### 20. 会话 RAG 记忆爆 Token 与工具冲突怎么办？
记忆：存 5-10 轮、滑动窗口+摘要记忆、每轮改写为独立查询防它指代丢失。
冲突：知识库与工具结果矛盾时按权威度、时间新旧、引用强制，必要时多视角输出或拒答，不硬编。Agent 选 ReAct 还是 FunctionCalling 看需多步推理还是单步执行，解析失败要重试+降级。
